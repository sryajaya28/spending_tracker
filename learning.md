# Learning: mistakes made on this project, and how to avoid them

Every item cost time, broke something, or annoyed the owner. **This file is now an index** (owner-approved workflow, `docs/workflows/README.md`): load only the area files your task needs, so a small change does not pay for the whole history. Anything in the Session log below is read in full when it is short enough; older entries are in `docs/learning-archive.md`.

| Your task | Load these (in `docs/learning/`) |
|---|---|
| Any change, always | `owner.md` (how the owner works) |
| About to push, merge, release or deploy | `release.md` |
| Database, migrations, RLS, Supabase, sync, Edge Functions | `data.md` |
| Editing `prototype/app.js` or other app code, event tracking | `code.md` |
| Layout, styles, iPhone and browser behaviour, dark mode, phone width | `ui.md` |
| Writing or running tests, QA, smoke tests | `testing.md` |
| Tier 1 (presentation only) | `owner.md`, `ui.md` |
| Tier 3 (data, access, money) | `owner.md`, `release.md`, `data.md`, `testing.md` |

**At the end of every coding session** append what you learned to the Session log below (mistakes, owner corrections, surprises, things that only worked after a detour), and add a short lasting rule to the right area file when it applies beyond that session. Keep each item short and say what to do instead.

## Session log (append a dated entry at the end of every coding session)

(Entries before 2026-11-03 are in `docs/learning-archive.md`.)
- 2026-11-13 (release 21, owner: "why couldn't you see session costs?"): the session's cost and token usage ARE readable with `get_session` (no session_id: `external_metadata.usage` and `context_usage`); I copied "not visible inside the session" from older COSTS rows without checking, and wrote a turn count I had not counted. Read the usage record when closing a task, and check `context_usage` during the task: this one reached about 228k tokens against the 120k budget because the release steps were added to the build session; for a task this size, hand the release to a fresh session.
- 2026-11-13 (release prompt, Fable 5.2 then Sonnet 5.5): no new mistakes. Two PRs appending a row to the end of `docs/COSTS.md` always conflict; after a rebase keep both rows. The release session is its own fresh session (`docs/tasks/RELEASE.md`), not the last build session.
- 2026-11-13 (Settings hub, Sonnet 5.5): moving cards onto sub-pages broke 18 e2e tests that opened `#/settings` and expected a card, so grep `tests/` for the route before moving anything and fix them in the same PR (a test that waited for the sign-out button on a long page needed a shorter viewport once the page got short). The owner sent design changes in small messages while I drew (sign out, sample data, profile, "theme"), and added the hidden bottom bar and the hub back arrow only after approval: ask in the first design message where the page is entered from and left to (tab bar, back button). `curl` to figma.com is blocked by the proxy, so Figma screenshots come inline (`enableBase64Response`). Cost not recorded in docs/COSTS.md (no usage record available inside the session).
- 2026-11-13 (coin transfer fee build, Sonnet 5.5): no owner corrections. The system prompt named a different branch than the owner's message; I built on the owner's branch (it held the task file). An existing test (`movehold`) moved crypto and silently started going through the new path: when a rule narrows by asset type, grep tests for that type first. Transactions days are collapsed: click `[data-act=days-all]` before waiting for a row. Event kinds without their own price (`tr.kind`) were skipped by `holdingCost`; a loaded event gets an `amount_minor` from its transaction, so `tradePrice` would silently price it at market: keep the `kind` skip unless `price` is set.
- 2026-11-13 (release 23, Sonnet 5.5): no new mistakes. `gh` is not signed in here, so the release PR was opened and merged with the GitHub tools and `ci_wait.js` could not be used; check the `e2e` run before merging (it was still running when the PR opened). `ship.js` leaves "no changelog entry" placeholders in the record: fill items, tests and gaps by hand.
- 2026-11-13 (overview-report mock, owner: "The budget bar is missing from your prototype", Sonnet 5.5): the design session removed the hero budget line and bar because "Overview will only show today's total spending" read like "drop budget info"; the owner never said that, and the hero bar is the app's budget cue. Do not strip an existing element from a mock unless the owner names it; list "removed" items in the request check and ask. The task file was only on `claude/overview-redesign-today-fa8yzm` (not on the branch the system prompt named): search `git branch -r` for the file before saying it is missing.
- 2026-11-13 (overview-report build, Sonnet 5.5): the session passed the 120k context budget (139k) because design fixes and the build ran in one continued session; a design hand-over should end the session and the build start fresh from the task file. Moving cards off Overview broke 8 tests (they read Overview for Money Flow, Spending, trend, Recent transactions, the Balance chip): grep `tests/` for the card or route before moving anything. `run_all.sh` only counts a test as passed when a line starts with `ok`; a new test that prints `name ok` fails there but passes under plain `node`. A test that adds an expense needs the account to have balance (the app blocks overdrawn expenses).
- 2026-11-13 (starter kit, Fable 5.2): built `starter-kit/`. `cmd | grep -q` under `pipefail` exits 141 (capture the output first); two kit folders shipped the same path, found only by a throwaway install, so run `kit.test.sh` after every kit change. Ran past the 120k budget: next time one small task per file group. General lessons also go to `starter-kit/template/docs/learning/`. Cost not recorded (no usage record).
- 2026-11-13 (README refresh, Sonnet 5.5): no new mistakes. README had drifted for about a week (household still "in development", old agent team); compared it with context.md, RELEASES.md and the code (currencies in `RATES`, support button) before writing.
- 2026-11-13 (landing phone section, Sonnet 5.5): no new mistakes. No Figma tool was available in this session, so the design step was skipped and the section was built straight from the owner's "go" (fast lane) with local light/dark/phone screenshots as proof; `tests/e2e/lent.js` failed once in a parallel full run and passed alone twice (its "no 500000 in the event" regex can match a random id): flaky, not caused by this change. Two real mistakes: (1) I branched from a stale local `staging` and recorded both demo videos against an old Overview; the owner spotted "Total balance" in the video. Run `git fetch` and branch from `origin/staging` before recording any asset that shows the app, and re-record after every rebase onto new UI. (2) I named a hero class `.chip`, which the app already uses (History button), and my `position: absolute` rule leaked into the app and broke three e2e tests; grep `styles.css` and `app/*.js` for a class name before adding a global rule, or scope it under `.land`.
- 2026-11-13 (desktop layout, Sonnet 5.5): the task file and WIP were only on `claude/desktop-layout-audit` (not on the branch the system prompt named, `staging`): `git branch -r` and `git log --all -- <file>` found it. A test that adds a first transaction lands on the congratulations screen, so set `state.ui.onbSeen = false; state.ui.congrats = false; state.ui.onbSkipped = true` before rendering Overview. Adding markup that is only hidden by CSS still counts in `textContent` and `$$eval`: `report.js` counted the hidden side column's headings; read Overview headings with `.main .grid >` (direct children). New test names must be added to the default list in `run_all.sh`. `staging_shot.js` needs the smoke login, so the dark, 390px, Indonesian and 1920px proof here was local Playwright shots (not saved in the repo).
- 2026-11-14 (redesign design phase, session 9, Fable 5.2 then Sonnet 5.5 after the owner's /model switch): redrew the Add transaction sheet and iterated Overview in Figma until the owner approved. Mistakes: (1) misread 'align the bottom part' of the currency prefix three times (bottom-of-box, centred, bottom of the p) before the owner showed a reference; the answer was plain text-baseline alignment: when a layout word is ambiguous ask for or find a reference first. (2) cloned a toast into an auto-layout frame and it landed in the flow, not at the top: set `layoutPositioning = 'ABSOLUTE'` after appending. (3) a clone of the Buy/Sell pill carried the wrong selected tab into the Sell frames; check the selected state after cloning. (4) the session ran far past 120k tokens and switched model mid-session (owner's command): hand over earlier. Surprise: the app has NO inline errors, only toasts (`events-submit.js`), and `Transaction added` is used for both expense and income. Figma screenshot URLs cannot be downloaded in this sandbox; screenshot inside `use_figma`.

- 2026-11-14 (Day page design, session 10, Sonnet 5.5): no repo mistakes. Figma: `use_figma` code must not put `await` inside a non-async arrow nested in an expression (parse error); `createAutoLayout` frames get a WHITE fill, clear `fills` on every layout-only frame; cloned Report frames keep `minHeight` (1180 on desktop) so `resize` does nothing until `minHeight = null`; the phone nav is ABSOLUTE at a fixed y, move it when the frame height changes. I told the owner the Income/Spent line would be drawn, but `topbar` never renders its subtitle: read the render function, not the call site, before listing controls. Placeholder `#8887a8` fails 4.5:1 on the tile fill (3.84), use muted there.
- 2026-11-14 (Day page, follow-up): before drawing a page, check that a user can reach it (grep the `data-act` that opens it, not only the route): the Day page was orphaned and four frames plus states were wasted. Also say so when a frame deliberately drops something the owner will expect (the Report tabs).
