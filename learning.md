## Session log (append a dated entry at the end of every coding session)

(Entries before 2026-11-03 are in `docs/learning-archive.md`.)
- 2026-11-11 (D1 task 1, Lent from account, Sonnet 5.5): no new mistakes. A branch cut before the app.js split cannot be rebased: `app.js` is now 17 lines. Method that worked: cherry-pick, take staging's `app.js`, then apply the old `app.js` diff hunk by hunk to the `prototype/app/*.js` file that holds the old text (a short script that needs each hunk's old text to match exactly one file). Applied the additive migration to the staging database only.
- 2026-11-11 (hide balance, Sonnet 5.5): I redrew the Overview hero in Figma from memory and left out the (i) tip and the change pill; the owner had to point both out. Before drawing an existing card, read its markup and list every element. The tracker writes `data-act` names with underscores (`toggle_hide_balance`). Cost not recorded in docs/COSTS.md (no usage record in the session).
- 2026-11-11 (hide balance release, Sonnet 5.5): `tools/ci_wait.js` said GREEN on PRs 63-65 while the real `ci` run (checks e2e, tier) was stuck Queued: it counted only the Vercel checks, so confirm the `ci` workflow run itself finished before saying CI is green. GitHub Actions stayed Queued for 6+ hours and could not be cancelled or re-run; the owner merged the release PR with the admin bypass after the staging regression passed.
- 2026-11-13 (overview spent hero build, Sonnet 5.5): no owner corrections. The task file lived only on the design branch (`claude/relaxed-carson-dsdwjd`), not on `staging`: find it with `git ls-tree` over `origin/*` and check it out into the new branch. A `//` comment inserted in the middle of a one-line Playwright chain silently commented out the rest of the line (the test then failed far from the cause): put comments at line ends or use `/* */`. A budget starts at its `start_month`, so a test that changes the period start day must also start the budget earlier. `todayIso` is a top-level `const`, not a window property, so a test cannot stub it: move the period start day instead. `tools/staging_shot.js` needs the merged change on staging plus smoke credentials, so the proof before merge is the local `tests/e2e/out/*.png` shots.
- 2026-11-13 (overview spent hero release 20, Sonnet 5.5): released on the owner's word without their staging check; Copilot never reviewed any of the PRs (`copilot-pull-request-reviewer` answered "insufficient remaining quota" after a manual `request_copilot_review`), so check its review status early and tell the owner instead of waiting. `gh` is not signed in here, so `tools/ci_wait.js` cannot run: read CI with `pull_request_read get_check_runs` and wait for BOTH `tier` and `e2e` of the `ci` run (a green Vercel check is not CI; `e2e` is skipped on purpose for docs-only PRs). The release path that worked with no `gh`: fold PR (`node tools/fold_changes.js`) -> release PR staging to main via the GitHub tool -> merge -> `node tools/ship.js --sha <merge sha> --tests ... --gaps ...` (needs `SMOKE_PROD_PASSWORD`, present in the environment) -> record PR. The smoke account is empty, so `staging_shot.js` shows the first-run screens: use `--setup` with `state.ui.onbSkipped = true; state.ui.onbSeen = false; state.ui.congrats = false` and in-memory data (no `save()`). `docs/READY_REPORT.md` is only the report template: send the report in chat and the PR, do not overwrite the file.
- 2026-11-13 (txn names + person filter, Sonnet 5.5): `node tools/path_tier.js` said Tier 1 for the split `prototype/app/*.js` files, but the tier table's role-visibility row makes it Tier 3; check the table, not only the script. The system prompt named `staging` as the dev branch while CLAUDE.md says never push to it: I worked on `claude/txn-who-filter` and asked the owner before pushing. Fast lane: I built first and drew the Figma frame afterwards; the order should be Figma link first. The new e2e assertions fail on the old code (checked by stashing `prototype/app`).
- 2026-11-13 (owner: "All people is cut off"): a new chip in a flex row that gives each `select[data-filter]` its own `flex-grow` weight collapses to 22 px unless it gets a weight too; I had only looked at my own screenshot at 390 px and missed that the Figma frame left out the search bar and month selector. Check the new control at 360 and 390 px, with every other filter present, and draw the whole screen in Figma, not just the changed part.
- 2026-11-13 (owner picked layout A; I had just deleted it): when the owner says "C looks good" while pasting a screenshot of A, ask which one before removing code; I restored A from git (`git checkout -- .`) and removed C instead. A temporary layout switch costs vertical space, so it distorts the spacing the owner is judging.
- 2026-11-13 (search in Occasion and Account lists, Sonnet 5.5): no new mistakes of the owner-facing kind. Found on the way: `dropdown.js` attached the `data-empty` "not found" note only to lists with an add entry (`data-cta`), so it never showed in the Category filter either; it now goes at the end of the list when there is no add entry. A test for the new rule must count the REAL options of the rebuilt account list (income adds two new-coin entries, an expense adds debt accounts), and the first `[data-act=add-txn]` on a phone is the hidden desktop button: use `.nav-add`.

For a database error, read the table's unique keys in `supabase/migrations` first.
